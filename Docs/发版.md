# CATVBA R2018 发布门禁与回滚手册

> 状态：CURRENT — NO-GO policy；DRAFT — future release process
>
> 更新日期：2026-07-16
>
> `release_eligible=false`

当前仓库没有可发布的 R2018 CATVBA。根目录两个 CATVBA 是遗留取证样本；现有
`.github/workflows/auto-release.yml` 不是合格发布器。任何文件存在、版本号、tag、workflow 成功、
源码静态检查或本地 ZIP 都不能替代 B28 构建和 G0-G7 证据。

## 1. 当前禁止事项

在 G7 为未过期 PASS 前，禁止：

- 把旧 CATVBA 复制到 Release、共享盘或 Production；
- 从旧 CATVBA Save As 或把它作为回滚 seed；
- 写、重建或强推 fork `main/dev`、上游仓库、正式 tag/Release；
- 用分支整树选边、squash 或无共同祖先合并制造发布树；
- 用 glob 自动选择 CATVBA，或由一次 tag push 直接发布；
- 把 Linux CI、Python 测试或 Office VBA 当作 CATIA B28 Compile；
- 现场热改 Production 后继续沿用原哈希、签名和门禁记录。

```text
  -> G5 Fleet-SPA / Fleet-FTA and failure isolation
  -> G6 returned audit, security, pilot and rollback
  -> G7 exact release-set approval
  -> publisher releases only approved immutable assets
```

Build Kit 是目标机构建输入，不是可安装 CATVBA；必须保持：

```json
{
  "catvba_artifacts": [],
  "compile_status": "not-run",
  "release_eligible": false
}
```

## 3. 门禁

| Gate | 当前状态 | 最低要求 |
|---|---|---|
| G0 INPUT-FROZEN | `PASS` | A 环境历史证据：fixed commits/blobs、manifest、resolver、审批范围闭合 |
| G1 KIT-READY | `BLOCKED` | 当前 preparation 尚未从新 evidence commit 生成和签发 Kit/bundle；旧 Kit 只保留历史证据 |
| G2 B28-ENV-ATTESTED | `BLOCKED` | R28/B28 SP/HF、VBA7/64、References、DSLS profile |
| G3 BUILT-UNVERIFIED | `BLOCKED` | 三个空白工程构建、Compile、保存重启、CATVBA 哈希 |
| G4 BASE-PROFILE-MATRIX-PASS | `BLOCKED` | Core 在 P-AB3/P-HD2/P-MD2 分别通过 |
| G5 FLEET-SPA-FTA-PASS | `BLOCKED` | SPA/FTA 分包、跨库调用和故障隔离通过 |
| G6 SECURITY-PILOT-READY | `BLOCKED` | 回传审计、安全包装、普通用户试点、安装和回滚 |
| G7 RELEASE-APPROVED | `BLOCKED` | 未过期 G0-G6、风险接受、审批和资产映射 |

输入、manifest、schema、generator 或制品变化建立新门链。SP/HF/Reference 变化从 G2 重跑；profile
变化从 G4 重跑；Fleet 包/调用变化从 G5 重跑。旧 Kit 对原输入仍是历史证据，但不得复用于新候选。
当前只有 G0 `PASS`；G1 在新 evidence/delivery cycle 完成前为 `BLOCKED`。旧 G1 PASS 仍是其原提交的历史
A 环境证据，但不授权当前 B28，也不证明 CATIA Compile、许可或运行。

## 4. 分支与 intake

- 逻辑上游：`verysolecd/Macro_menu:dev`；
- fork `main/dev`：对应上游镜像，由独立同步流程维护；
- 唯一重构写分支：`doylenehemiah6893-afk/Macro_menu:codex/dev-review-report`；
- Build Kit/发布器不得自动 fetch 后写 `main/dev`；
- WORK 分支只通过审定 intake 吸收 upstream dev，不整体合入 main；
- upstream 占用 `catvba_refactor/**`、override base 漂移、portable path/VB_Name/FRM-FRX 冲突时 fail-closed；
- 已绑定 Kit/证据的提交不 rebase/force-push。

详见[上游 intake 与 fork 同步设计](superpowers/specs/2026-07-13-catvba-upstream-intake-design.md)。

## 5. 许可证与发布包

目标资格：

```text
(AB3 OR HD2 OR MD2) AND SPA AND FTA
```

| 包 | 发布地位 |
|---|---|
| Core | 默认、启动必需；不早绑定 SPA/FTA |
| Fleet-SPA | 默认发布，独立 CATVBA/Reference/证据，惰性调用 |
| Fleet-FTA | 默认发布，独立 CATVBA/Reference/证据，惰性调用 |
| Baseline Extension | 只在通过的 AB3/HD2/MD2 profile 部署 |
| CATIA Licensed Optional | ST1/DL1/LO1/DMN/KWA 等指定席位 |
| External Integration | Excel/网络/外部 COM，另做安全规格 |
| DevTools/Quarantine | 永不进入普通 Production |

P-AB3、P-HD2、P-MD2 都固定包含 SPA+FTA；P-ALL 或现场组合只作补充，不能替代三个最小 profile。

Core、SPA、FTA 分别从空白工程构建。SPA/FTA 未安装、Reference/加载/checkout 失败时 Core 必须仍可
启动，另一扩展不受影响；但默认 Fleet release 的 G5/G7 不得 PASS。

## 6. Build Kit 与 B28

Kit 至少包含 fixed Git inputs、组件来源、FRM/FRX bundle、package/capability、分包源码、生成模块、
导入顺序、Reference allowlist、目标测试、证据模板、逐文件哈希和确定性 ZIP。

B28 每个包必须：

1. 在干净 R28/B28 空白工程导入；
2. 只启用允许 B28 Reference；
3. Compile、保存、关闭 CATIA、重启、再次 Compile/HealthCheck；
4. 记录完整 References GUID/version/path/MISSING；
5. 绑定 profile、Kit ID、源码/FRX/制品 SHA；
6. 返回 A 环境做只读审计。

跨 CATVBA 调用必须经过 B28 spike；若 `SystemService.ExecuteScript` 的 Variant 返回、路径或错误行为不
可靠，G5 保持 BLOCKED，不允许用临时文件交换绕过。

## 7. 当前 workflow

历史上的 `.github/workflows/auto-release.yml` 曾在 `v*` tag 上用 glob 猜测 CATVBA 并创建 Release；该历史
意图不满足门禁，已于 2026-07-16 改为 comments-only marker，不含 trigger、permission 或 job。仓库中不再保留
可执行的 tag release job。它从未构成 B28 Compile、许可或发布批准证据，也不得从历史提交恢复执行。

当前 `.github/workflows/repro.yml` 只做 fresh-clone 实现验证：Linux 执行完整测试和确定性双 Kit 比较，
Windows 使用原生 CPython 3.12 检查 bootstrap/doctor、collector、CMD wrapper 和 pyz。它上传 JSON receipt；只有
`CURRENT.json` 与控制文件认证通过时，才额外上传固定路径的 Discovery operator-bundle ZIP。它从不搜索、上传或发布
CATVBA，也不会把 preparation 状态改成可发布。

未来拆为：

1. `release-validate`：只验证 G7、资产白名单、release-set 版本和全部哈希；
2. `publisher`：经受保护环境人工批准后发布已验证包，不重新 checkout 猜测文件。

## 8. 安装与回滚

候选策略是同一 release-set、物理三文件、逻辑原子发布：Core、Fleet-SPA、Fleet-FTA 版本必须匹配。

- Production 安装根、CATIA 宏库注册和惰性加载语义由 P-PROD 验证后批准；
- 不允许独立混装不同 release-set；
- 安装失败回滚整个 release-set，不留下部分注册；
- 运行期单扩展故障可保持 Core，但 Fleet 标为 DEGRADED；
- 正式回滚只切回有效 G7、哈希匹配且未 withdrawn 的完整 R28 release-set；
- CATVBA 回滚不等于模型数据回滚，模型使用独立备份。
